# Seam Video

Video editor where edits are defined as JSON (`.seam` files). No absolute timecodes — clips defined by source in/out, everything shifts automatically when you add/remove/reorder.

## Repo Structure

pnpm monorepo:

- **`@seam/core`** — Schema (Zod), types, layout resolver, compile pass. Pure logic, no I/O.
- **`@seam/compositor`** — Platform-neutral WebGPU compositor + `buildRenderList`. Walks a resolved timeline into draw/group/fill commands (shapes = analytic SDF fills, `cornerRadius` = mask, extension node types = own draw + children placed through the type's anchor function — a map's basemap + pinned children) and composites them; abstracted over a `RenderBackend` (device, frame upload, target) so the same code runs on the preview's canvas and the renderer's headless Dawn device. Preview↔render parity by construction.
- **`extensions/map`** (`@seam/extension-map`) — the **Map extension**: the `map` node type + the `pin` field. Pure entry (`.`): definition, types (merged into core's unions by declaration merging), `sampleMapState`/`sampleZoom`/`samplePin`, `MapView`/`lngLatToWorld`/`truncateToFraction` and the pin→pixel anchor function. **`./render`** entry: the same extension with its rasterizer attached — pmtiles byte-range → MVT decode (`@mapbox/vector-tile`+`pbf`) → Mapbox-GL style eval (`@maplibre/maplibre-gl-style-spec`, headless) → Canvas2D fills/lines/labels; no OpenLayers/WebGL/DOM. `TileSource` (+pool) owns the async fetch+decode and an in-memory cache of **unpacked** tiles (never rasters), like an Image; `drawBasemap(ctx, view, style, tileProvider)` is fully synchronous. ONE rasterizer (`render/rasterizer.ts`) serves both hosts. **Map `theme`** (`"light"` default / `"dark"`, non-animatable): `applyTheme(style, theme)` derives the dark style from the bundled OSM Bright (`render/osmBrightStyle.ts`, a module) by an HSL colour transform — no second style JSON. (Replaces the old `packages/map`.)
- **`@seam/media-source`** — Platform-neutral remote-media byte layer shared by the preview (browser) and the renderer (node): `BlockStores`/`BlockStore` (bounded `Range: bytes=a-b` block cache, one byte budget, in-flight dedupe, read-ahead, eviction by a caller-supplied priority), `PlannedSource` (mediabunny `CustomSource` facade carrying a **tag** every read is attributed to), `cutsFromTimeline` (pure: resolved timeline → `Cut[]` with absolute placement + source window) and `CutPlanner` (warms each upcoming cut's bytes keyframe→out point ahead of the playhead; priority = timeline distance), plus `sniffStaticKind(head)` (static source kind from magic bytes / `<svg` — both hosts' static decoders classify by content, never by name). Replaces mediabunny's `UrlSource` for `http(s)://` sources on both hosts — see the **Remote media** convention.
- **`@seam/renderer`** — Headless video renderer. Decodes + composites a resolved timeline in-process (mediabunny + `@seam/compositor` on Dawn WebGPU), encodes mp4, and mixes audio via OfflineAudioContext. Text + maps rasterize on `@napi-rs/canvas`; SVG statics alone go through node-canvas (`svgImage.ts`). No melt/ffmpeg, no fabric.
- **`@seam-media/cli`** — `render`, `resolve` commands (Commander). Decoupled from the preview/editor apps (those will ship as binaries).
- **`@seam/preview`** — Electron + React live preview with file watching. Exports `Player`, `Timeline`, `VideoCanvas`, `TransportControls` for reuse.
- **`@seam/editor`** — Electron + React editing app. Owns React UI, platform abstraction (Electron / Web), exports `App` + platform for host shells. (Desktop-only for now — mobile layout was removed pending a dedicated UI pass. The fabric frame editor was removed with the `graphic` type; a unified on-canvas editor is planned.)
- **`@seam/web`** — Web (browser) shell for the editor. OPFS-backed storage with `projects/` and `clips/` directories.
- **`@seam/html-renderer`** — Static HTML host for the editor.
- **`extensions/*`** — First-party **extensions** (workspace packages `@seam/extension-*`, to be published as `@seam-media/extension-*`), registered by every host through `createSeam([...])`. They import only the public extension API (types from `@seam/core`). **`extensions/adjustments`** (`@seam/extension-adjustments`): the colour adjustments — six keyframeable fields on every visual node + one WGSL colour stage. **`extensions/map`**: see below. See the **Extensions** convention and `docs/extensions.md`.
- **`generator-server`** — Python/FastAPI sidecar for transcription (faster-whisper) and audio enhancement (Resemble Enhance). Not wired through the JS monorepo.

## Commands

```
pnpm test              # all tests (core + renderer + editor pure-logic + preview audio scheduler, Vitest)
pnpm build             # build all packages
pnpm --filter @seam/preview build && pnpm --filter @seam/preview dev   # preview dev
pnpm --filter @seam/editor build && pnpm --filter @seam/editor dev     # editor dev (Electron)
pnpm --filter @seam/web dev                                            # editor dev (web / OPFS)
npx tsx packages/cli/src/index.ts render <file.seam>                   # render a .seam to mp4
```

## Renderer (`@seam/renderer`)

| File | Role |
|------|------|
| `src/render.ts` | `renderSeamToFile(seam, seamPath, outPath, options)` — orchestration: compile/resolve (`@seam/core`) → mix audio → per output frame `buildRenderList` (`@seam/compositor`) → decode/rasterize active drawables → composite on Dawn WebGPU → read back → encode/mux mp4 (mediabunny). Extension nodes (maps) rasterize on demand (no disk pre-pass); shapes never leave the GPU. Remote sources: one `BlockStores` registry per render (`options.remoteCacheBytes`, default **1 GiB** — the audio mix walks every cut up front and the frame loop walks them again, so the whole project's spans should stay resident; the 192 MiB store default is the browser's) threaded into `FrameSource` + `renderAudioMix`, and a `CutPlanner` over `cutsFromTimeline(timeline)` fed `planner.update(t)` every frame (prints request/hit/eviction stats under `SEAM_NEXT_TIMING`); both disposed in `finally`. On any failure the mediabunny `Output` is **cancelled** (closes the half-written target) — an open `FileHandle` collected by GC is a fatal error on Node ≥ 24 and would mask the real exception |
| `src/gpu.ts` | `createGpuDevice()` — Dawn (`webgpu` pkg) headless device; pins the `create()` instance at module scope (a GC mid-`mapAsync` would otherwise segfault — see `dawn-node-instance-gc` memory) and installs the WebGPU globals once |
| `src/NodeBackend.ts` | Headless `RenderBackend` for `@seam/compositor`: uploads frames via `writeTexture`, renders to an offscreen `rgba8unorm` target, reads it back through a ring of N (`bufferCount`, default 3) `mapAsync` staging buffers in flight |
| `src/frameSource.ts` | Per-tick frame provider for the compositor's sync `getFrame`: clip (mediabunny forward sample **cursor** + rotation bake from `track.rotation` — no ffprobe), static (`staticKind.ts` sniffs the bytes: svg → node-canvas/librsvg via `svgImage.ts`, raster → `@napi-rs/canvas`, else video freeze), text (Skia+Pretext), extension nodes that draw themselves (`nodeRasterizers.ts` — a map's basemap, on-demand RGBA; `"extension" in node` tells them from core drawables). `rect`/`circle` never reach it (analytic fills in the compositor). Each drawable addressed by its `DrawCommand.drawTime` (container-local elapsed, all comp offsets/speeds folded in). The clip cursor is **keyframe-aware for high `speed`**: a forward jump ≥0.25s checks `EncodedPacketSink.getKeyPacket` (metadata-only) and re-seeks when a keyframe lies between cursor and target — decode cost per output frame is bounded by GOP length instead of draining every skipped sample; same-GOP jumps still advance sequentially (re-seek there would re-decode from the keyframe *behind* the cursor). Parity-tested against random-access `getSample` in `__tests__/frame-seek.test.ts`; bench: `bench/speed-seek.ts` |
| `src/mediaInput.ts` | `isRemoteSource` / `resolveSourcePath` / `openMediaSource(src, basePath, stores?)` — the one place a node `source` turns into a mediabunny input: `http(s)://` → **`PlannedSource`** over the render's shared `BlockStores` (`@seam/media-source`: bounded Range blocks, timeline-ranked cache — see the **Remote media** convention), else `FilePathSource` joined on the .seam's dir. Used by `frameSource.ts` (clips; static images fetch URLs via `loadImage`) and `audio.ts`, both of which take the registry from `render.ts` (callers that pass none share a process-wide default); `nodeRasterizers.ts` opens remote byte-range sources (pmtiles) with pmtiles' `FetchSource`. This is what lets the editor's **remote .seam** render straight off Seam Cloud. Tested against a local Range-capable http server in `__tests__/remote-source.test.ts` (byte-identical frames) and `__tests__/planned-source.test.ts` (planner warms every cut with bounded requests → live decoder reads are cache hits; farthest cut shed first under pressure and re-warmed when the playhead arrives). **mediabunny ≥ 1.61.5 floor** still applies: `CustomSource` sits on the same `ReadOrchestrator` whose earlier versions deadlocked on far seeks (a read arriving while every worker was busy got queued and never dispatched; 1.48.1 hung a 98-cut remote render within ~300 frames — symptom on Node ≥ 24 was a FileHandle-GC crash on the output mp4, not an error). Pinned by `__tests__/url-source-far-seek.test.ts` (two concurrent far reads on a `parallelism: 1` `UrlSource` over a 20 ms-latency local server; 1.48.1 hangs on the first pair) — a downgrade fails there. See the `urlsource-deadlock` + `remote-block-cache` memories |
| `src/svgImage.ts` | `rasterizeSvg(pathOrUrl)` — SVG statics rasterize through **node-canvas (Cairo + librsvg)**, not `@napi-rs/canvas`'s `loadImage`, whose SVG path silently drops embedded `<image href="data:…">` content; librsvg renders images, text (fonts via `registerNodeCanvasFonts`) and clip paths, from a file path or an `http(s)` URL (remote .seam). Pinned by `__tests__/svg-static.test.ts` (embedded data-PNG pixel + text ink, file and http) |
| `src/staticKind.ts` | `classifyStatic(pathOrUrl)` → `svg` / `raster` / `unknown` from the file's **leading bytes** (`@seam/media-source`'s `sniffStaticKind`; fs read for local paths, a bounded `Range` + first body chunk for http). `frameSource.decodeStatic` routes on it: svg → Cairo, raster → Skia, unknown → video freeze frame. **Never classify a static by its name** — a remote .seam's sources are `…/api/media/<id>/file?token=…` with no extension, which is how remote comment-card SVGs went through Skia and lost their avatars. Same test file |
| `src/hdrToSdr.ts` | **HDR → SDR input conversion** (seam's opinionated default; the preview gets the equivalent from Chromium). `isHdrSample` (transfer tagged `hlg`/`pq`) routes a decoded sample through `HdrToSdrConverter`: one cached libavfilter graph per decode cursor (node-av bundles **jellyfin-ffmpeg**, so `tonemapx` is in-process) running the validated chain `tonemapx=tonemap=hable:desat=0:p=bt709:t=bt709:m=bt709:r=pc:peak=100:format=yuv420p` then `scale=in_color_matrix=bt709:in_range=pc,format=rgba`. `toAvFrame` refs the decoded AVFrame (no copy). Behaviour is **pinned empirically** in `__tests__/hdr-to-sdr.test.ts` (lossless x265 grey fixtures: HLG 25/50/75/100 % → 48/94/158/243, PQ 203 nit → 173) because the HLG linearization differs between jellyfin revisions (bundled build: standard OOTF γ=1.2 with 75 % = scene white; jellyfin master: BT.2446-B) — a node-av bump that changes the look fails there. SDR samples are untouched |
| `src/audio.ts` | `renderAudioMix()` — `OfflineAudioContext` (`node-web-audio-api`) mix mirroring the timeline: per clip/audio node trim (`[in,out]` region decode) + speed (`playbackRate`, pitch-shifted) + gain envelope + crossfade ramps, summed at the destination. Recurses compositions AND extension containers (a clip pinned to a map still plays its audio). Rendered concurrently with the frame loop |
| `src/text/canvasShim.ts` | Installs the bundled fonts + an `OffscreenCanvas` polyfill so `@seam/core`'s `layoutText`/`drawTextLayout` run server-side on `@napi-rs/canvas` (Skia) |
| `src/text/fonts.ts` | Registers the bundled font families with `@napi-rs/canvas` GlobalFonts (text nodes + map labels — the only server-side font registry now) |
| `src/loudness.ts` | **`--agc`** offline mastering pass over the rendered mix (BS.1770-4 / R128, pure Float32 DSP, no preview counterpart — export-time only): `LoudnessAnalyzer` (K-weighting via libebur128's bilinear forms so any sample rate hits the 48 kHz table; prefix-summed power → O(1) integrated/short-term/range loudness, −70 LUFS absolute + −10 LU relative gates), `measureTruePeak`/`truePeakPerSample` (4× windowed-sinc oversampling), `limitTruePeak` (stereo-linked lookahead brickwall: required gain → sliding min over 5 ms → one-pole 80 ms release → box-smoothed, so the ceiling is a hard guarantee; offline = no delay), and `applyAgc` = **rider** (short-term 3 s loudness steered to target on a 100 ms grid, 0.5 s attack / 2 s release, ±12 dB cap, holds under −50 LUFS so room tone never gets lifted) → **trim** (static gain onto the integrated target exactly) → **limiter** (−1 dBTP). Defaults −14 LUFS / −1 dBTP = Reels / Shorts / TikTok normalisation. `render.ts` runs it between the OfflineAudioContext mix and the AAC encoder when `RenderOptions.agc` is set and reports `RenderResult.loudness` (`AgcReport`); the CLI prints it. Pinned on synthetic signals in `__tests__/loudness.test.ts` |
| `src/nodeRasterizers.ts` | `NodeRasterizers` — the headless host of extension node types that draw themselves (`NodeTypeDef.rasterizer`, e.g. the Map extension's): creates each type's rasterizer on first use with the Node `RasterHost` (`createCanvas` = `@napi-rs/canvas`, `openSource` = byte-range `NodeFileSource` via `fs/promises` or pmtiles' `FetchSource` for http, `requestRepaint` no-op), **awaits `ensure` then calls `draw`** and reads the canvas back as RGBA. One set per render run, disposed with the `FrameSource` (closes file handles). Pinned children are NOT drawn here — they're ordinary nodes the compositor places via the extension's anchor function |

## Preview (`@seam/preview`)

| File | Role |
|------|------|
| `src/renderer/components/Timeline.tsx` | rAF clock, single WebGPU canvas. Repaints are otherwise frame-driven (`coordinator.onFrameAvailable`), so two explicit paints cover content with no async frame (shapes / text / extension nodes): once when WebGPU init resolves, and on every new timeline when `coordinator.hasAsyncFrames` is false (with clips/statics present it waits for their first frame instead — painting immediately would flash them out while buffers re-prime) |
| `src/renderer/components/Player.tsx` | Wraps Timeline + VideoCanvas + TransportControls |
| `src/renderer/components/VideoCanvas.tsx` | `<canvas>` shell. `mode="fit"` (default, `maxWidth/maxHeight: 100%` fit-to-container — all the Player needs) or `mode="free"` (pan/zoom: trackpad pinch = ctrl+wheel zoom-about-cursor, two-finger/wheel pan, drag-to-pan, double-click + `resetSignal` re-fit; reports `onViewChange`). The `<canvas>` element identity is stable across modes (only CSS/handlers swap) so toggling never re-registers/re-inits WebGPU. Backing res is always content size regardless of mode. Optional **`overlay(surface)`** render-prop draws a layer positioned exactly over the displayed video in any mode/zoom/pan; **`GizmoSurface`** = `{rect, toNorm(clientX,clientY)→{x,y} in [0..1]}` — the reusable basis for viewport gizmos (spatial-property handles etc.). No consumer yet |
| `src/renderer/media/gpu/WebGPURenderer.ts` | Thin adapter over `@seam/compositor`'s `Compositor` + a `BrowserBackend` (canvas device, `copyExternalImageToTexture`, swapchain target). The compositing logic itself (blit + filter shaders, FBO groups, fills) lives in `@seam/compositor`, shared with the renderer. `buildRenderList` is imported from there too |
| `src/renderer/media/FrameCoordinator.ts` | Manages ClipPlayers, decodes video frames via mediabunny. Each flat clip carries `sourceRate` (clip `speed` × enclosing comp speeds, static). **High-speed clips** (dense ±1s window would span >8 source-seconds, i.e. rate >4) switch their `ClipBuffer` to **sparse mode**: `setWantedTimes` on a stable quantized grid (30 targets/output-second) instead of `setWantedRange` — the buffer decodes only frames the display will sample, via a keyframe-aware cursor mirroring the renderer's `frameSource.ts` (re-seek iff a keyframe lies between cursor and target, `EncodedPacketSink.getKeyPacket` metadata-only; same-GOP jumps drain). Memory bounded by target count, decode bounded by GOP. **Remote sources**: `setTimeline` builds a `CutPlanner` (`@seam/media-source`) over the flat clips (one `Cut` per flat clip: absolute start/end + source window) on `mediaStore.stores`, and `reconcile` feeds it the playhead every tick, so each upcoming cut's bytes are warm before its ±1 s decode window opens and the byte cache ranks by timeline distance (disposed with the coordinator). **Audio plays at any speed** and registers with the composed `sourceRate` (not `clip.speed`) — the scheduler uses it as both playbackRate and the source→output time mapping, so clips nested in speeded comps pitch/schedule correctly (mirrors the renderer's `effectiveSpeed`). At extreme rates the per-packet source nodes + rate×-realtime decode are wasteful but hold up (granular-synth-style scheduling); no mute threshold by design. **Audio pre-rolls like video**: `reconcile` starts a clip's audio run as soon as its start enters the `LOOKAHEAD` window (`startClip(id, sourceTime, {at, until})` with context times from `contextTimeFor`), not when the playhead crosses in — a cold `AudioDecoder` takes longer to yield its first buffer than a short clip lives, so start-on-entry left runs of 0.1 s clips silent |
| `src/renderer/media/MediaStore.ts` | One mediabunny `Input` per source URL (video + audio tracks shared by every `ClipBuffer` / audio sink of that source). `http(s)://` URLs (Seam Cloud streams) go through a **`PlannedSource`** over the store's `BlockStores` (`@seam/media-source`); `blob:`/`file:` keep `UrlSource` (+ `BlobSource` fallback) |
| `src/renderer/media/StaticStore.ts` | Decodes one frame per `static` node (image or video freeze-frame). The kind comes from the url's **leading bytes** (`sniffStaticKind` from `@seam/media-source` over a bounded-Range/first-chunk fetch) — blob: and remote `…/file?token=…` urls have no extension, so names are never consulted. Raster images decode with `createImageBitmap(blob, { imageOrientation: "from-image" })` so EXIF orientation matches the headless renderer — must stay explicit. **SVG** goes through an `<img>` + `drawImage` at its intrinsic size instead: Chrome's `createImageBitmap` rejects SVGs that embed an `<image href="data:…">` (comment-card exports keep the avatar that way) with "The source image could not be decoded", while `<img>` renders them. Caveat: an `<img>`-loaded SVG can't see the page's `@font-face`, so `font-family="Liberation Sans"` falls back to a system face in the preview while the renderer uses the bundled TTF |
| `src/renderer/media/TextStore.ts` | Rasterises text nodes to OffscreenCanvas via Pretext |
| `src/renderer/media/nodeRasterizers.ts` | Browser host of extension node types that draw themselves. **Page-lifetime** rasterizers — `rasterizerFor(seam.nodeTypes, type)`, one per Seam instance + type, never disposed, so their caches (a map's decoded tiles) stay warm across timelines and `<Timeline>` remounts; `clearRasterizers` drops per-timeline state. The browser `RasterHost`: `createCanvas` = `<canvas>`, `openSource` = the resolver the shell injects with **`setByteSourceResolver`** at boot (OPFS `FileSource` on web, `file://` `FetchSource` on Electron), `requestRepaint` → `subscribeRasterWake` listeners. `FrameCoordinator.applyContentSizes` calls `rasterizer.draw(node, drawTime, contentW, contentH)` per frame for each extension draw (synchronous — from whatever is decoded now; nested-comp time mapping lives in the render list alone) and keeps the returned canvas for `getFrame`; a wake repaints via `onFrameAvailable` |
| `src/renderer/media/AudioScheduler.ts` | Web Audio API master clock + per-clip scheduling. A clip plays as a **`Run`** `{at, sourceTime, until}`: every decoded buffer is scheduled at `at + (ts − sourceTime)/speed`, so `at` in the future = pre-roll (buffers queue ahead, `stop(until)` at the clip's end), `at` in the past = late decode (elapsed portion skipped, sync kept). `play()` stamps the clock *before* `resume()` (currentTime is frozen while suspended, so the first ticks already map timeline→context). **Scrub bursts are anchored to the first buffer's arrival**, not to the `scrub()` call: the gain envelope + `until` + finalize timer are applied in `pump` when the first buffer lands; a burst superseded before that is dropped with no automation. `lastStartLatencyMs` / `localStorage["seam:audio-debug"]="1"` log decode→first-buffer latency. Tested with a fake `AudioContext` + gated sink in `__tests__/AudioScheduler.test.ts` (inject the context via the constructor) |
| `src/renderer/components/TimelineContext.ts` | Timeline contexts. Besides `useTimeline` (transport), exposes **`useTimelineFrame().subscribeFrame(cb)`** — a read-side seam delivering the composited RGBA after each frame. `Timeline` downscales the swapchain canvas (`drawImage` → 2D scratch, longest edge ≤256) and pushes pixels to subscribers; no-op when nobody listens (cost is opt-in), throttled to ~30fps during playback, primes one frame on subscribe while paused. Also **`useTimelineMedia()`** → `getMediaSize({type, source, orientation})` + `subscribeMediaSizes(cb)`: probed clip/static display dims **by authored source** (`FrameCoordinator`/`StaticStore` keep a by-source map that survives `setTimeline`, and fall back to it in `getIntrinsicSize` so layout doesn't jump while buffers re-prime). Useful for thumbnails / colour sampling / analysis. Swap in a true offscreen-readback producer later without touching consumers |

## Editor (`@seam/editor`) — pure-logic modules

| File | Role |
|------|------|
| `src/renderer/compile.ts` | Thin shim: `compileDocument(seam, doc, options)` → `seam.compileSeamFile` |
| `src/renderer/nodeBin.ts` | Reads/writes `comp.bin` and `comp.binItem` (first-party schema fields) |
| `src/renderer/nodeScript.ts` | Reads/writes `comp.script`; enable/disable/bake helpers |
| `src/renderer/splitTool.ts` | `sliceAtPlayhead(seam, doc, t, only?)` — splits **every** clip/audio/composition under the playhead in one operation, or just the indices in `only` (the selection). The left half keeps `id`/`start`/`offset`; the right half is a plain run member with neither (no crossfade authored on halves). Sibling `start` anchors are rewritten to keep landing on the same moment (source points in the right half retarget to it, percent points re-expressed against the containing half). An authored `duration` is split across the halves; looping nodes don't split. In the toolbar: no selection → everything under the playhead at the root; with a selection → only the selected nodes, each in its own container (`editContainer` + `descendToContainer`, deepest container first) |
| `src/renderer/resolveLocal.ts` | `descendToContainer(seam, resolvedRoot, doc, containerPath, globalTime)` — maps the global playhead into a nested container's inner-timeline time. Per level `inner = (in ?? 0) + (t − comp.timelineStart) · comp.speed`. `resolvedRoot` must be resolved **`uncropped`** (the editor timeline is); nested containers are re-resolved uncropped so `rContainer.children` is 1:1 with authored children. Shared by slice, attach and bracket |
| `src/renderer/attachTool.ts` | Toolbar **`applyAttach(seam, doc, resolvedRoot, t, primaryKey, secondaryKeys)`** — path-keyed: first selection is the primary; each secondary is lifted (run-aware) to the END of the **primary's container** as the head of its own run, anchored to the primary **without moving**: the anchor point is the playhead, pulled inside the secondary's own span when the playhead is before/past it (and inside what the primary plays), and `offset` is the distance from that point back to the secondary's current start. `anchorAt`: clip/audio/composition primaries get a source point (`"id@<sec>"`); every other type gets the bare id (its start). Cross-container secondaries carry their position over in global time. Returns the new doc + the moved keys (kept selected so the anchor lines show). Gives the primary an id if it has none. Bin-rooted primaries are out |
| `src/renderer/bracketTool.ts` | Toolbar **`applyBracket(seam, doc, resolvedRoot, currentTime, primaryKey, secondaryKeys, side)`** — align an edge of each secondary to the primary (only secondaries are edited). Target: secondary **attached to the primary** (its `start` anchors the primary's id, same container) → match the *same* edge; otherwise **legato** → the bracketed edge meets the primary's *opposite* edge. With **no secondaries**, the primary brackets against the **playhead**. Mechanism: start edge of a node with `start` → shift its `offset`; start edge of a run member → left-trim (`resizeChild`); end edge → always right-trim (there are no end anchors, so bracket-end never moves a node). Deltas are snapshot-measured and converted into each subject's container-local output time, so primary/secondaries can sit in different containers. Bin-rooted selections skipped |

## Conventions

- **Seconds everywhere** — frames only at the encode boundary (default 30fps).
- **Seam instance** — everything that depends on the installed extensions goes through an explicit instance, `createSeam(extensions)` from `@seam/core`; there is no module-level default (two projects with different extension sets can share a process, and a missing instance is a type error). Each host creates one at boot: `packages/cli/src/seam.ts`, `packages/preview/src/seam.ts` (main + renderer processes), and the editor shells' `main.tsx` (editor + web — wire both), which pass it as `<App seam>` and into the platform (`detectPlatform(seam)` / `new WebPlatform(seam)`). The renderer takes it as `renderSeamToFile(seam, …)`. In the editor, components/hooks use `useSeam()` (`seamContext.ts`, provided by `App`) and pure-logic tools take **`seam` as their first argument** (`sliceAtPlayhead(seam, doc, t)`, `resizeChild(seam, …)`, `descendToContainer(seam, …)`, `locateNode(seam, …)`, `applyPropertyEdit(seam, …)`, `layoutTree(seam, …)`, …). Every host currently installs the same list (`[adjustments, map]`, with `map` from `@seam/extension-map/render` — every host draws) — adding a first-party extension means touching all four host sites. Tests call `createSeam()` themselves (with the extension when they exercise it). Functions that don't depend on the extension set (`resolveSpatial`, samplers, anchor/loop helpers) stay plain exports. Roadmap, decisions and the growing extension contract: **`docs/extensions.md`**.
- **One `children` array; time comes from runs.** Array order is **z-order only** (later = on top). A node lands at `(start ?? end of the previous node, 0 for the first) + offset`: no `start` = it continues the previous node's **run**; a `start` heads a new run. `start` = bare number (absolute seconds in the container) \| `"id"` (start of sibling `id`) \| `"id@50%"` (fraction of its output span) \| `"id@10"` (source second 10 — pre-trim media time of a clip/audio, pre-window inner time of a composition). No `end` anchors, no offset inside the anchor — shifting is the node's `offset`. Anchors may point anywhere in the array (the resolver walks the dependency graph; cycles/unknown/duplicate ids throw). Ids: no `@`, not numeric. **`offset`** on a run member = gap after the previous node, **negative = overlap + crossfade** (resolved `transition`/`transitionOut`, clamped to both neighbours); on a head it is a plain shift (so a hard overlap needs its own run). Composition duration = **max end** of its children; time before 0 is cropped. An overlay with no `start` plays AFTER the previous node — give it `start: 0` or an anchor. (`attachments`, the `empty` node, `transition` and `end` anchors are gone; no converter exists.)
- **Node types**: core's `clip`, `audio`, `static`, `data`, `text`, `rect`, `circle`, `composition` (`CORE_NODE_TYPES`), plus those extensions contribute — `map` (the Map extension). (`graphic` — the fabric.js keyframed sub-scene — was removed; see the shapes/map bullets below. No fabric, no node-canvas anywhere.)
- **Shapes `rect` / `circle`**: first-class nodes placed by the ordinary spatial model. **No intrinsic size** — their natural box is the parent, so `size` IS the shape (bare number = px, `%` = of the parent; `size: 100` → a 100×100 box, a `circle` is the ellipse inscribed in its box). `fill` (default `"black"`; `"none"`/`"transparent"` skips it), `stroke`, `strokeWidth` are **keyframed**; the stroke is drawn **inside** the box (border-box). `duration` required unless both `start`/`end` anchors are set (like text). Rendered **analytically in the shared WGSL shader**: `RenderList` emits `FillCommand`s with a `ShapeGeometry` (`kind` roundrect/ellipse, `radius`, `outerInset`, `innerInset`; fill = inset by the stroke, stroke = ring) and the fragment shader computes signed-distance coverage with 1px screen-space AA (`fwidth`) — no texture, scale-independent, both hosts identical. Fill keys are stable per resolved node (`WeakMap`) so the backends' colour tiles cache; colours re-rasterize only when the sampled colour changes.
- **`cornerRadius`** (universal `SpatialFields`, `Keyframed<Length>`): rounded-corner mask on ANY node's final rect. Bare number = px; `%` resolves against the **shorter side** of the rect, so `"50%"` turns a square into a circle and a rectangle into a pill (the avatar-mask case). On a leaf it's the `mask` on its `DrawCommand`; on a composition/map it forces the FBO path and masks the composited `GroupCommand`. Same shader geometry as the shapes (kind roundrect, no insets).
- **`map` node** (the Map extension, `extensions/map` — core has no map code; see the Extensions bullets): used like a `static` with a camera — `source` (pmtiles), `duration`, keyframed `latitude`/`longitude`/`zoom` (zoom tweens in scale space)/`mapOpacity`, `theme`, `paths[]` (`color`/`progress`/`lineWidth` keyframed, `points` static, optional `id`). Inner canvas = `contentWidth`/`contentHeight` (default 100% of the parent) — both the raster size and the layout space of its **`children`**, which are ordinary nodes of ANY type (clip, static, text, rect, composition, …) placed exactly like a composition's children (runs + `start` anchors, time 0 = map start, speed 1) — but they never extend the map: its `duration` is authoritative. A **`pin`** (a field the Map extension contributes to every visual node — it rides in the resolved node's `ext` bag with `anchored: true` — `Keyframed<Pin>`, only read on map children) places the node geographically: `{latitude, longitude}` or `{path: index|id, position?}` (`position` defaults to that path's live `progress` — rides the reveal head). The render list calls the map definition's `createAnchors` once per frame (camera sampled at the same map-local `drawTime` the basemap rasterizes for) and runs each child through the returned function, and `resolveBoxProps(…, anchor)` puts the node's `origin` on that pixel with `translation` as a **px offset from the pin**. `resolveSpatial` keeps `spatialInput` on `anchored` nodes (the baked rect is meaningless). In the render list a map — any extension container — is a container: its own `DrawCommand` (`clip: <the node>`, `contentW/H` = inner canvas, no extension fields) then the children walked in the map's viewport; extension fields/rotation/opacity/`cornerRadius` route it through an FBO like a composition. Audio in map children mixes (both mixers recurse maps); `flattenResolved`/CLI `flat` recurse too.
- **`isMediaSource(child)`** = `clip | audio | static` — anything with an external `source` path. Use this for blob-URL preloading, path rewriting, export bundling. Source-time-aware paths (split, attach, JSON inspector) keep the narrower `clip | audio` check because static has no in/out trim.
- **Compositions carry first-party `bin`, `binItem`, `script`** (not metadata conventions). The compile pass in `@seam/core` resolves them:
  - `binItem: "<id>"` adopts the named bin entry's body; lookup is lexically scoped (nearest-enclosing wins).
  - `script` runs at compile time, receives the bin-resolved composition as `currentNode`, returns the replacement composition.
  - `compileSeamFile(doc, { runScripts: false })` skips scripts (used by the editor's timeline panel so blocks map 1:1 to authored children).
- **Two resolved timelines** in the editor (both off the active document — the root doc, or the CC-cut preview while that mode is active):
  - `playerTimeline` — full compile (bins + scripts). Drives the canvas.
  - `editorTimeline` — `runScripts: false`. Drives the timeline panel so drag/trim/delete writes back to positions the user can see.
- **No drill-down navigation**: the editor always operates on the root document; there is no "enter into a clip/composition" view. CC Cut is the one editor mode, a modal flag (`ccCut` in `App.tsx`), not a view variant. Instead, compositions **expand inline** on the timeline (`timelineTree.ts` → recursive `TimelineGroup` in clip-boxes) and are edited in place.
- **Path-keyed selection (single source of truth)**: `App` holds `selection: string[]` of path keys (`children.0`, `children.3.children.1` — see `nodePath.ts`). The UI layer resolves each key to a node. Nested blocks support select / resize / delete / drag at any depth; mutations run the existing pure tools (`resizeChild`, `attachNewItems`, …) against the target composition through the `editContainer` lens. **`binItem` expansions are editable too** — their children address a `bin.<id>` root (`bin.intro.children.0`), so the same tools rewrite the shared bin entry and the edit propagates to every reference (Phase 3, intentional — the binItem block keeps its dashed-border/`Boxes` marker as the signal). Some legacy toolbar actions (bin/word/transcribe in `ControlsBar`, CC-cut) consume **root child indices** derived via `rootIndicesFromKeys` and ignore nested selections; attach, bracket, compose and slice are path-keyed and work at any level (`ControlsBar` gets both `selectedIndices` and `selection`). Selection display: `selection[0]` (the attach primary) renders **solid**, every other selected block **dashed**, regardless of type.
- **Timeline = runs** (`timelineTree.ts` + `DesktopTimeline` + `dropRegions.ts`): each run is laid out on one row with a **dotted underline** in the strip beneath it (`ROW_GAP`); runs pack into rows by z — a run goes strictly below every *earlier* run it overlaps in time, non-overlapping runs share rows (`packRuns`). The root body is re-resolved `uncropped` so blocks stay 1:1 with authored children. One drag pass handles everything: grab a block (the whole selection comes along when the grabbed block is part of it, landing contiguous **in selection order**) or drag files/media in → `dropTargetAt` → `moveNodesTracked` / `insertNodes` with `{before}` (drop before a head = the anchor transfers) or `{start}` (the strip under a row or the ruler = "new run here" at the cursor's time). **Shift held at the grab** nudges the grabbed nodes' `offset`s live instead (history like a resize). **Shift pressed after the grab** (a move drag, or a file drag) snaps a *new-run* drop to the nearest node start/end within 10px (else the playhead — a node edge in reach always wins) (`dropTargetAt(…, snap)`): the head gets that edge's exact time as a plain numeric `start` with no offset — an authored time, not an anchor. Every new-run **move** (snapped or not) passes its time through `dropTime.ts`'s `timeAfterLift`: the drag is aimed at the pre-move layout, but lifting nodes ripples their run, so the time follows the latest surviving node edge at or before it into the post-move layout (drag A out of `[A,B,C]` onto C's start → the new run starts with C where C ends up). Dragging a run's dotted underline **vertically** re-stacks it in the array (`moveRun`). Anchoring is a second step: the toolbar Attach button, then the anchor lines. Resize deltas in a nested group scale by the group's window `scale`. `flattenGroups`/`flattenDropRegions` track each container's *true* content-top (`RULER_HEIGHT + ROW_GAP` at root, then accumulated clip-box tops) — the root drop-region rect still starts at y=0 as the hit-test floor.
- **Schema is the single source of truth**; types mirror it. Defaults flow through Zod (`children` defaults to `[]`).
- **Default canvas**: `DEFAULT_CANVAS_WIDTH = 1080`, `DEFAULT_CANVAS_HEIGHT = 1920` (portrait). Used by App.tsx, preview main, VideoCanvas, CLI render/resolve.
- **Spatial model**: every node lays out via `origin` + `translation` + `size` (no more `top/left/right/bottom/width/height/position`):
  - `Length` value = `number | "p%" | "p% +/- n"`. Each property substitutes its own percent default when only a pixel number is given.
  - `origin` (point on the item, default `"50%"` = center): percent reference = item's own size. `0` evaluates to center.
  - `translation` (point in parent where origin lands, default `0` = center): percent reference = parent's content size. `0` = center; `"0%"` = top-left.
  - `size` (final pixel size, default `"100%"` = post-objectFit natural rect): percent reference = post-objectFit size. `100` (bare) = literal 100px box.
  - `rotation` (degrees, clockwise, default `0`, animatable): rotates the node about its `origin` point. Baked onto `SpatialRect.rotation` (+ `originX`/`originY` for the pivot) only when authored — non-rotated rects stay a plain `{x,y,width,height}` so existing equality checks hold. Both renderers rotate the textured quad in the WGSL vertex shader via the shared compositor (a rotated composition takes the FBO path so the whole group rotates as one).
  - Final rect = `(translation - origin, size)`. Renderers consume this `SpatialRect` directly — no further objectFit math at draw time. `objectFit` only determines what `size: "100%"` evaluates to.
  - `inset` (+ `insetMode`) (`inset` feature, **composition-only**, animatable): per-edge crop in the text-padding shorthand but `Length`-valued (`%` → left/right=width, top/bottom=height). Order: objectFit/`size` build the content box → `origin`/`translation`/`size`/`rotation` place **that box** (placement decoupled from the crop — no drift) → `inset` clips a window + `SpatialRect.sourceRect` `{u0,v0,u1,v1}` records the visible sub-rect → `insetMode` (`window` default / `center` / `fit` / `cover`) maps the window within the placed box: window/center/fit change the output rect (`sourceRect` = the window); `cover` instead tightens `sourceRect` to a centered box-aspect crop of the window and outputs the full box (no second clip region needed — same visible result as objectFit cover, reusing the pipeline). `sampleInset` (core) reuses `sampleLength` per edge; **all of this lives in `resolveBoxProps`** — both renderers consume `SpatialRect` + `sourceRect` and need no mode-specific code (net scale stays uniform across all modes). Both renderers consume it via the shared compositor: a `crop: vec4f` uniform maps the quad into the sub-rect (comp FBO group; `sourceRect` forces the FBO path). To crop a clip/image, wrap it in a composition — the windowing cost is an authored opt-in.
  - `distort` (**composition-only**, animatable as one value): corner-pin / perspective warp of the composited content — `{x0,y0,…,x3,y3}`, eight optional `Length`s clockwise from top-left, `%` against the comp's **inner canvas** (`contentWidth`/`contentHeight`), bare number = px offset from the corner's own default. **Purely visual — never touches `SpatialRect`/layout** (content may spill the box). Rides on `ResolvedComposition.distort` (authored keyframes, like `opacity`); `RenderList` samples it in output time via `sampleDistort`, maps the visible window's corners through the full-canvas homography (`@seam/core` `layout/distort.ts`: Heckbert square→quad, shared by both hosts) into target px as `GroupCommand.corners`, forces the FBO path, and widens the scissor to the corners' AABB. The compositor's vertex shader places each vertex at its pinned corner and writes the per-corner homogeneous weight (`quadWeights`) into `clip.w`, so UVs interpolate projectively (true perspective, no diagonal crease). Non-convex pin sets fall back to unit weights. Pinned on real Dawn in `packages/renderer/src/__tests__/compositor-distort.test.ts` (seam lands at the projective, not bilinear, position).
  - `contentWidth`/`contentHeight` (composition inner canvas / text canvas / map raster) are an **animatable `Keyframed<Length>`**. A bare number = literal pixels; a percentage resolves against the **immediate parent container**; **default = `"100%"` of the parent** (no ascent to the root — a composition is self-contained). The **root** composition must use a **static pixel number** (no parent reference, and it defines the output canvas — `%`/keyframes throw). The spatial pass preserves the authored value on the resolved node and bakes a t=0 pixel value into `intrinsicWidth`/`intrinsicHeight` (static consumers); the per-frame renderers sample `contentWidth` against live parent dims via `sampleContentDim` (shared by both hosts, so an animated inner canvas resizes the FBO + reflows text/map textures and **children re-layout against the live canvas each frame** — when a node's inner canvas animates, `resolveSpatial` keeps its children's `spatialInput` so they re-evaluate). The compositor surfaces the per-frame text/map size on `DrawCommand.contentW/H`; the renderer threads it through `collectDrawables`→`frameSource`, the preview through `FrameCoordinator.applyContentSizes`→`TextStore`/`MapStore`.
- **`duration` + `overflow`/`underflow`**: on clip / audio / composition `duration` is always the **output length**; the strategies say how the content (`[in, out]` or the inner window, at `speed`) fills it — `overflow` when the content is longer (`trim-end`/`trim-start`/`trim-center`/`stretch`), `underflow` when shorter (`extend-*`/`stretch`/`loop`). Both default to **`stretch`**, so plain `{in, out, duration}` derives the rate `(out−in)/duration`. `speed` + `duration` together are valid only with a non-stretch strategy (then `speed` is the content rate). `text`/`rect`/`circle`/`static`/`map` just show for `duration` (always required).
- **`underflow: "loop"`** (clip / audio / composition): replay the content from its start until `duration` is filled, last cycle cut short — a clip/audio's `[in, out]` at its own `speed`, a composition's inner window (so a comp holding clip `[0.5, 1.5]` with `duration: 10` shows that second ten times). The resolved node keeps ONE cycle plus a **`loop: { period, phase }`** marker (`ResolvedLoop`; `period` in node-local output seconds, `phase` = how far into a cycle the node starts, non-zero only after a window crop). `ResolvedComposition.duration` stays the single-cycle length (so `duration × speed` is still the inner span) while `timelineEnd − timelineStart` is the whole looped span. **The node's own keyframes (opacity, spatial, `volume`, …) run over the full span; only the content time loops.** Consumers go through `@seam/core`'s `layout/loop.ts`: `loopLocalTime(loop, t)` (compositor `RenderList` wraps a clip's `drawTime` / a comp's inner time per frame; editor `descendToContainer` + attach source anchors), `loopIterations(loop, span)` (renderer `audio.ts` = one buffer-source slice per cycle sharing the decoded region; preview `FrameCoordinator.collectClips` = one `FlatClip` per cycle, each with its own `ClipBuffer` + audio registration so cycles preload like sequential clips — buffers/playing sets are keyed by `FlatClip`, `flatByClip` maps a node to its cycles), and `unrollLoops(children)` (per-cycle plain clones with window-cropped children — `flattenResolved`, CLI `flat`, and both mixers' composition recursion). Timeline block label gets a `↻`; the expanded group shows one cycle. `cropChildrenToWindow` advances `phase` instead of trimming the cycle.
- **Crossfades** (`transitions` memory) — a run member with a negative `offset` overlaps the previous node; the resolver stamps the effective overlap as `transition` (incoming) and a mirrored `transitionOut` on the previous node (for audio's fade-out), on any producing type (not `data`). Heads never fade. **Video** crossfade = fade the *incoming* element's alpha in over its first `transition` s; the outgoing one is occluded as it ramps (over-composite) — both renderers fold the fade into the draw/group opacity (routing a crossfading comp through the FBO). **Audio** sums, so both sides ramp (gain envelopes in the renderer's OfflineAudioContext mix and the preview's `AudioScheduler`/`FrameCoordinator`). Linear, matched preview↔render. Known gap: the stamps are not adjusted when the crop at 0 (or a composition window) cuts into a fade.
- **Composition `volume`** — an animatable `Keyframed<number>` (0..4, like clip `volume`) that **uniformly scales every audio-bearing descendant** (clips / audio / nested comps); it multiplies through nesting and composes with each clip's own `volume`. Sampled in the composition's **output** time (against `comp.duration`), like opacity. The **root** composition's `volume` rides on `ResolvedTimeline.volume` and scales everything. Applied in the two output mixers — the renderer's `audio.ts` (`collectAudioNodes` accumulates a `VolumeEnv[]` of enclosing-comp volumes, folded into the gain curve) and the preview's `FrameCoordinator` (`collectClips` threads a `compVolumeAt(globalTime)` multiplier per clip, applied in the per-tick `setClipVolume`). **Not** applied by the editor's transcription mixer (`compositionAudioMix.ts`) — that exists to make audio audible to whisper, not to honor output mixing.
- **`pitch`** — length-preserving audio pitch shift in **semitones** (fractional ok, schema-clamped ±48, **not animatable**) on `clip`, `audio`, and `composition`. Independent of `speed` (which shifts pitch naturally); semitones **add** through nesting (comp pitch + clip pitch; the root's rides on `ResolvedTimeline.pitch`). Implemented once in `@seam/core`'s `createPitchShifter` (`src/audio/pitchShifter.ts`) — a jungle-style dual-delay-line granular shifter built purely from Web Audio nodes, so the **same graph** runs in the preview's `AudioContext` (`AudioScheduler.registerClip(..., pitch)`, shifter between the buffer sources and the clip's GainNode; `FrameCoordinator.collectClips` composes the semitone sum) and the renderer's `OfflineAudioContext` (`audio.ts` inserts it between source and gain) — parity by construction. Known character: grain-rate (10 Hz) amplitude sidebands and ~`0.1·|2^(st/12)−1|/2` s latency (≈50 ms at ±1 octave). Realtime shifters hold looped modulation sources until `dispose()` (wired into `unregisterClip`). Like `volume`, NOT applied by the editor's transcription mixer.
- **`ChildTimingFields`** shared interface for `in`, `out`, `overflow`, `underflow`, `id`, `start`, `end`, `metadata` — extended by Clip, Composition.
- **Clip/audio `out` is optional when `duration` is set**: `{in, duration}` means `out = in + duration` at speed 1 (the schema requires one of `out`/`duration`; `speed` + `duration` stays mutually exclusive). Every reader of an authored `out` goes through `@seam/core`'s **`clipOut(clip)`** (`layout/clip-span.ts`) — resolver (`clipBaseSpeed`/`naturalDuration`/leaf), editor split/resize/attach/anchor tools, transcribe + normalize decoders. `out` may be below `in` (see **Reverse playback**), so readers that need the span in playback order use `clipPlayRange` from the same file. Tools that rewrite the span (split's right half, a right-handle resize) materialise `out`.
- **Reverse playback (clip / audio)**: authored as **`out < in`** or a **negative `duration`** (`{in: 5, out: 2}` ≡ `{in: 5, duration: -3}`: shows source 5 → 2). Either signal reverses and they never cancel (`{in: 2, out: 5, duration: -3}` plays 5 → 2 too); output length is `|duration|` when set (a target the overflow / underflow strategies fill, like a positive one), else `|out − in| / speed`; `speed` stays positive; `in === out` / `duration: 0` are schema errors. Compositions are not reversible. **Resolved nodes keep `sourceIn < sourceOut` and `speed > 0` and carry `reverse: true`** — so region decodes, byte cuts, loop maths and comp speed products are untouched — and every time mapping goes through `@seam/core`'s `layout/clip-span.ts`: authored `clipPlayRange` (span in playback order) / `clipIsReversed` / `clipNaturalDuration` (`|out − in| / speed`, ignoring `duration`), resolved `clipSourceTime(node, local)` / `resolvedPlayStart` / `resolvedSignedRate`. **Never write `sourceIn + t·speed`.** The resolver runs overflow/underflow on the negated source axis, so `trim-end` / `extend-start` etc. mean *playback* start/end (trim-end on 10 → 4 keeps 10 → 8); window crops and `unrollLoops` eat the playback start off the high end; source-mode anchors use the signed rate. Consumers: renderer video = `frameSource.decodeReverse` (a window of the last 12 decoded samples, refilled keyframe → target only when the playhead steps below it; same "latest sample ≤ t" pick as the forward cursor, pinned byte-exact in `__tests__/frame-reverse.test.ts`); renderer audio = the decoded region is sample-reversed (padded to full length first, so a region past the file's end leads with silence — `__tests__/audio-reverse.test.ts`); preview video = the ordinary `ClipBuffer` window (it is a source range either way; backward refills stop at the frames already held, and sparse mode fills descending); preview audio = `AudioScheduler.pumpReverse` (walks down the source in chunks — 0.25 s then 1 s — each decoded forward and scheduled sample-reversed on the absolute sample grid so chunks abut; `__tests__/AudioSchedulerReverse.test.ts`). Editor: split / resize / attach / anchor tools work in playback order with the signed rate (left handle = playback start = `in`; split halves keep the sign of an authored `duration`), blocks get a `◀` label, transcription always extracts the range forward.
- **Composition `speed`/`duration`** mirror clips: the "source" is the inner window (`[in, out]`, default whole timeline). `speed` scales the window's playback (output = `windowSpan / speed`); `duration` sets the output length (derived rate = `windowSpan / duration`). Mutually exclusive. The resolved `ResolvedComposition.speed` carries the net rate (base × any overflow/underflow stretch) — overflow/underflow still layer on top when an anchor forces a different target, exactly as for clips.

- **Extensions (stage 1: fields + colour stages).** A `SeamExtension` is `{ name, fields?, colorStage?, nodes? }` (`packages/core/src/registry.ts`). **`fields`** are flat, first-class node fields declared as DATA (`FieldSpec`: `key`, `nodes: "visual"`, a `type` — see the stage-2 bullet for the kinds — `min`/`max`, `default`, `animatable`, plus presentation hints `label`/`group`/`step`/`unit`/`softMin`/`softMax`) — that one declaration drives the per-instance Zod schema (`buildSeamFileSchema(registry)`; node schemas are `.strict()`, so a field no installed extension contributes is a **validation error**, and a key colliding with core or another extension throws at `createSeam`), the resolver (authored values ride verbatim on resolved visual nodes as **`ext`**, and on the root as `ResolvedTimeline.ext`), the render list (`sampleFields` samples the NUMERIC ones → **`fields`** on every draw/fill/group command, sampled in the node's own time like opacity; a container with any authored field takes the FBO path; root fields wrap the whole frame in one group) and the editor (`extensionProps(seam)` → Properties rows). **`colorStage`** = `{ slots, wgsl, entry, prepare(values, out) }`: a per-pixel colour function **fused into the compositor's fragment shader**, which is now ASSEMBLED per instance (`new Compositor(backend, seam)`; preview: `<Timeline seam>`/`<Player seam>` → `WebGPURenderer(seam)`). Stages run in registration order on gamma-encoded RGB after the texture sample, one pass per quad; each owns a run of `vec4f` slots in the `ext` uniform array that follows the fixed members (`U_ROT`/`U_CROP`/`U_CORNERS`/`U_SHAPE`, then `EXT_BASE`); `prepare` fills them per draw from the sampled `fields` (missing key = default). WGSL identifiers must be prefixed. **Adjustments** (`extensions/adjustments`) is the first one: `brightness`, `contrast`, `saturation`, `gamma`, `temperature`, `tint` — the old `adjust`/`colortemperature` maths moved verbatim (order brightness/contrast → gamma → saturation → temperature×tint), `colorbalance`/`bypass`/the `filters` array/the fold-by-type rule are GONE (clean break; stack by nesting compositions). The stage runs on every quad while the extension is installed (as the hard-coded filters did); at its defaults it changes no 8-bit pixel (the rounded-coefficient Y'CbCr round trip drifts ≤ ~0.24 of a step — checked exhaustively in a float32 simulation), so an identity bypass would be a perf choice only. Pinned on real Dawn in `packages/renderer/src/__tests__/compositor-adjust.test.ts` (pixel values captured from the old `filters` path, leaf + FBO-group, plus tint / keyframes / root / nesting / no-stages). `packages/renderer/src/bench/filter-passes.ts` still measures the fused-vs-pass-chain trade-off for the future shader command (each extra full-frame pass ≈ **0.06 ms at 1080p**).
- **Colour management: both sides are pinned to BT.709 for SDR — renders are true, tagged BT.709 limited-range, and SDR inputs decode with their tagged matrix (709 when untagged); HDR is tone-mapped.** Render exports convert the composited RGB to YUV with the **BT.709 matrix** (not swscale's 601 default) and carry complete colour metadata (H.264 VUI + mp4 `colr`: bt709 primaries/transfer/matrix, tv range). Both halves are **upstream in `@mediabunny/server` ≥ 1.61.5** (JC's fix; we carried it as a pnpm patch on 1.48.1 until then — the patch is gone, the tripwires below stay): (1) **encode** — the video encoder sets the codec context's colour properties before open (→ VUI + a complete `decoderConfig.colorSpace`, which makes mediabunny emit `colr`) and routes RGB-family→8-bit-YUV conversion through an ffmpeg `scale=out_color_matrix=bt709:out_range=tv` filter graph — necessary because `sws_scale_frame` on a `getContext`-configured context ignores frame colour properties and defaults to BT.601. Covers libx264 **and** hw encoders (h264_nvenc gets picked when present). (2) **decode** — `toRgbSample` (what `copyTo({format:"RGBA"})` runs, i.e. the renderer's every clip frame via `frameSource.ts`) used the same legacy swscale path and so converted ALL YUV with BT.601 regardless of tags; the fix refs the decoded frame, fills unspecified properties with BT.709 limited range, and scales through an **unconfigured** `SoftwareScaleContext` (frame-based path, honours the tags). Before the encode half existed the 601 decode + 601 encode cancelled for untouched footage (and RGB-native text/shapes were wrong); with only the encode half, 709 footage was decoded 601 and baked that way — hence both halves ship together. Tripwires: `packages/renderer/src/__tests__/color-metadata.test.ts` (encodes pure red, asserts tags, raw Y'CbCr ≈ 63/102/240, AND that decoding it back to RGBA gives red ≥247 — a 601 decode lands at 233). A dependency change that loses either half fails there. **HDR sources (HLG/PQ-tagged, e.g. iPhone Dolby Vision 8.4 = HLG BT.2020) are handled** separately — the preview via Chromium's tag-aware WebCodecs→sRGB conversion, the renderer via `hdrToSdr.ts` (jellyfin `tonemapx` in-process, see the renderer table); same intent, not bit-identical (Chromium's HLG curve is its own). Static images still differ (browser `createImageBitmap` vs Skia, no ICC). Everything in the middle is **8-bit `rgba8unorm`, gamma-encoded, never linearized** (no `-srgb` formats; colour stages/blending operate on gamma-encoded values).
- **Remote .seam** (Cloud menu, web only): **Export Remote .seam…** writes `<name>-remote.seam` with every media source replaced by its Seam Cloud streaming URL (`…/api/media/<id>/file?token=<session token>`), for a final `seam render` that streams off the cloud instead of downloading. - **Remote media (`@seam/media-source`)** — both hosts read `http(s)://` sources through the same block layer instead of mediabunny's `UrlSource`. Why: `UrlSource` sends **open-ended** `Range: bytes=N-` and resets the stream once its positional prefetch is satisfied — the server keeps pumping until the reset lands (measured ~35 MB/s against Seam Cloud), nothing is cacheable, its prefetch grows exponentially past a cut's out point, it never requests the *next* cut before the player asks, and its LRU knows nothing about the timeline. Ours: fixed 1 MiB **blocks** fetched with bounded `bytes=a-b` (adjacent misses coalesce ≤ 8 MiB per request, concurrent fetches of a block dedupe, sequential patterns get exponential read-ahead — up to 8 blocks for the player's own streams, capped at 2 for planner prefetches since those stop at a cut's out point the store can't see), one shared byte budget (`BlockStores`, default 192 MiB in the browser, 1 GiB in the renderer), and eviction by **priority = timeline distance from the playhead** (`CutPlanner.distanceOf`): the index (first block + moov, read while the planner's `PlannedSource` tag is `INDEX_TAG`) is pinned, a cut's blocks rank by `|cut.start − playhead|` (0 inside it), the player's own reads outside any known span sit at `liveDistance` (10 s). Cut spans are **learned, not computed** (mediabunny packets expose no byte offsets): the planner reads a cut's packets — video from `getKeyPacket(sourceIn)`, audio from `getPacket(sourceIn)`, to `sourceOut` — through a per-source prefetch `Input` whose `PlannedSource.tag` is the cut id, and the store's per-tag block **set** *is* the span (`coverage`/`footprint`; the min..max `rangeOf` is informational only — a cut's packet reads interleave with lazy sample-table reads near the moov, so its range can span most of the file); later live reads of those blocks are attributed to the cut. Warming is nearest-first within `horizon` (20 s), one prefetch per source at a time (`maxConcurrent` 2 across sources), abandoned if the playhead jumps away, gated by `fits()` (don't warm a cut that could only land by displacing nearer content), terminal `failed` on error (no retry spin), and a done cut whose span got evicted re-warms only after the playhead has moved ≥ 0.5 s (`REWARM_STEP`) — chained via a macrotask so a run of cache-hit prefetches can never starve the host loop (a range-based coverage + microtask chain livelocked a real render at 270 % CPU before this). Two rules keep it from thrashing: a **running prefetch counts as distance 0** and the **8 most recently used blocks are never evicted** (`protectRecentBlocks`) — without them the farthest cut's freshly fetched block was evicted beneath its own packet iterator and re-fetched per packet (livelock found in `planned-source.test.ts`). `PlannedSource` is a `CustomSource` with `maxCacheSize: 0` + `prefetchProfile: "none"` so every demuxer read reaches the store as issued; its fixed 2-worker orchestrator means a third concurrent cache-miss read queues behind two in flight — fine once spans are warm. `BlockStore.read` returns subarrays of cached blocks (callers copy); blocks are copied out of a coalesced response so evicting one frees its memory. Measured on the 98-cut remote project (CLI, `SEAM_NEXT_TIMING=1`): 74 s wall vs 84–95 s on `UrlSource`, every request bounded. Cloud side: `fileResponse` streams a `createReadStream({start,end})` slice; an unsatisfiable range currently comes back **502 via openresty, not 416** (the handler throws) — harmless to the store (it never asks past `size`) but a server bug to fix.

- **`canvas` (node-canvas) is used for ONE thing: SVG statics** (`packages/renderer/src/svgImage.ts`, Cairo + librsvg — `@napi-rs/canvas`'s SVG loader drops embedded `<image href="data:…">`). Everything else server-side rasterizes on the prebuilt `@napi-rs/canvas` (Skia): text, map tiles and labels. The fabric graphic system that was node-canvas's big consumer is gone. **It must never reach the `@seam/cloud` Docker image** — it compiles from source when no prebuilt matches (needs pkg-config + cairo/pango dev libs the image doesn't have); the cloud only uses `@napi-rs/canvas`, `canvas` is a renderer/CLI dependency. pnpm was resolving it into the cloud's tree as vitest → jsdom's optional peer, so the root `package.json` carries `pnpm.overrides["vitest>jsdom"] = "-"` (pnpm's remove-dependency syntax). Verify with `pnpm why canvas --filter @seam/cloud` (must be empty).
- **No Node version pin needed.** The renderer's native addons (`@napi-rs/canvas`, `canvas`, `webgpu`/Dawn, `node-av` via mediabunny, `node-web-audio-api`) ship prebuilt N-API binaries that are ABI-stable across Node versions, so `engines` is just a `>=22` floor and `.nvmrc` tracks `lts/*`.
- **Electron binary is installed by `dev`, not by `pnpm install`.** Electron ≥ 45 has no npm postinstall hook (the binary downloads lazily on first `require("electron")` or via its `install-electron` bin), and electron-vite 6 reads `path.txt` directly and fails with `Error: Electron uninstall` when it is missing. So the editor/preview `dev` scripts are `install-electron && electron-vite dev` — a no-op (~0.2 s) once the binary is present. Deliberately NOT a `postinstall`: the web Dockerfile installs `--filter @seam/web...`, which includes the editor and thus electron, and must not download a Linux Electron. `electron-vite build` never needs the binary. Also: the `file` scheme is registered with `corsEnabled: true` in both main processes — Chromium 156 (Electron 45) enforces the CORS-enabled-schemes list even with `webSecurity: false`, so without it the dev renderer at `http://localhost:5173` cannot `fetch("file://…")`.
- **Timeline block colors** in TimelinePanel's `BLOCK_COLORS` — `rect`/`circle` are deep magenta (`#b03a8f` bg / `#d957b8` border), `map` is green (`#2f7a5a` / `#4bb886`), distinct from text's rose and composition's violet.
- **Font fallback (CJK + emoji)**: the bundled body font (Liberation Sans) is followed everywhere by **Noto Sans CJK JP** + **OpenMoji**. The family names + `withFallbackFamilies()` live in `@seam/core`'s `text/fallbackFonts.ts` (single source of truth); every `ctx.font` string appends them — text nodes (core, both sides) and map labels (both sides via the Map extension's `buildLabelFont`, which emits weight/style keywords + the base "Liberation Sans" family + fallbacks as a canvas font string). Registration: the renderer registers all three with `@napi-rs/canvas` GlobalFonts (`installFonts` — text nodes AND map labels, one registry); the browser registers FontFaces via `loadFallbackFonts` (warmed at boot in preview/editor/web mains). TTFs live at `packages/renderer/fonts/{noto-cjk-jp,openmoji}/` and `packages/preview/src/renderer/fonts/` with their licenses (Noto = OFL, OpenMoji = CC BY-SA 4.0). Emoji render in **colour everywhere** now (Skia COLR server-side, Chromium in the preview) — the old monochrome Cairo path went with node-canvas. The CJK TTF is a 35 MB variable font, so browser loads are fire-and-forget (web bundle is heavy — subset later if it matters).

## Tech

- TypeScript (ES2022, strict, ESM)
- Vitest for testing
- Zod for schema validation
- Electron + React (electron-vite) for editor + preview shells
- React 19 + Monaco for JSON/script editing
- Commander for CLI
- mediabunny for audio/video decode + encode/mux (browser via WebCodecs; Node via `@mediabunny/server`/NodeAV); remote media bytes come through `@seam/media-source` (bounded-Range block cache + timeline-driven planner) rather than `UrlSource`
- WebGPU for compositing — browser canvas in the preview, headless Dawn (`webgpu` pkg) in the renderer, via the shared `@seam/compositor`
- @napi-rs/canvas (Skia) for server-side text rasterization
- `@seam/extension-map` (DIY: pmtiles + `@mapbox/vector-tile` + `pbf` + `@maplibre/maplibre-gl-style-spec` + Canvas2D) for `map` nodes — browser preview and headless renderer alike, no OpenLayers/jsdom/WebGL/fabric
- pmtiles for byte-range vector/raster tile reads (OPFS on web, fs on node)
- node-web-audio-api (OfflineAudioContext) for the renderer's audio mix
- **No zip anywhere.** "Export Project…" copies `.seam` + media into a picked **folder** — the flat folder IS the project layout the desktop app/CLI open. Web: `showDirectoryPicker` + `stream().pipeTo` (Chromium-only; others get a descriptive error — Export .seam / Seam Cloud are the alternatives), with per-entry lazy OPFS `File` acquisition (`acquireExportFile`; OPFS Files are snapshots — holding them across a long export causes `NotReadableError`). Electron: main-process `showOpenDialog(openDirectory)` + `copyFile`. **Web import** = `WebPlatform.importFiles(File[])`: batch importer behind the browse page's page-wide drop zone (both tabs, folder-drop aware) and MediaBrowser's Upload Media / Upload Folder buttons — media → `importClip` (fingerprint dedup + unique rename) first, then `.seam` files become projects with sources basename-flattened and mapped through the batch's rename map (`mapDocumentSources`)
